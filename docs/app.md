# アプリの使い方

craft-automation の運用（レシピ管理・一括実行・PhotoCraft のバージョン管理）をブラウザの画面で行うアプリ。自分の PC の中だけで動く。要件は [requirements.md](requirements.md)、技術選定は [adr/0001-app-stack.md](adr/0001-app-stack.md)。

## 準備（初回のみ）
1. **Python 3.10 以上**を入れる: https://www.python.org/downloads/
   - Windows はインストーラーの最初の画面で「Add python.exe to PATH」にチェックを入れる
   - macOS 標準の python3（3.9）では動かない
2. このリポジトリを PC に置く（`git clone https://github.com/osamu-sej/craft-automation`、または GitHub の「Code → Download ZIP」を展開）

## 起動
| OS | 操作 |
|---|---|
| macOS | Finder で `run-app.command` をダブルクリック |
| Windows | エクスプローラーで `run-app.bat` をダブルクリック |
| ターミナル | `python3 app/launch.py`（Windows は `py -3 app\launch.py`） |

- 初回は依存パッケージの導入で数分かかる（リポジトリ内の `.venv/` に入る。2回目からはすぐ起動する）
- ブラウザで http://localhost:8501 が開く。開かなければこのアドレスを手で開く
- **終了**: 起動したターミナル（黒い画面）のウィンドウを閉じる
- macOS で「開発元を確認できない」と出たら、`run-app.command` を右クリック → 「開く」。ZIP でダウンロードした場合に出る

## 最初にやること: PhotoCraft の導入
1. 左の「**バージョン**」を開く
2. 「導入する版」でピンの版（`.photocraft-version` の版）を選び、「**導入**」
3. 本家リリースから、この PC の OS 向けの CLI を取得し、SHA256 を検証してから `.bin/<版>/` に展開する（macOS 約 20MB、Windows 約 30MB）。Windows の ARM64 は、ネイティブ版があるリリース（v0.3.0 以降）ではそれを、ない版では x64 版（エミュレーション）を使う

左のサイドバーの「使用バージョン」で、実行に使う版を切り替えられる。

## 一括実行
1. 「**一括実行**」でレシピ・入力フォルダ・出力フォルダを指定する
   - パスはリポジトリ基準の相対パス（例: `samples/in`）か絶対パス
   - Windows の「パスのコピー」で付く `"` はそのまま貼ってよい
   - macOS は Finder でフォルダを選んで ⌥⌘C でパスをコピーできる
2. 処理件数や注意（出力名の重複、既存ファイルの上書き、レシピの警告）を確認して「**実行**」
3. 実行中も画面は操作できる。「キャンセル」で止められる
4. 終わると、成功・失敗の件数、実行コマンド全文、失敗理由、出力のサムネイル、入出力の比較が出る
5. 成功したら「このレシピを vX.Y.Z で検証済みにする」で `tested_with` を記録できる

処理されるのは入力フォルダ直下の画像だけ（サブフォルダは対象外）。入力と出力を同じフォルダにはできない（元画像が上書きされるため）。

同じ名前の出力になる画像（`a.jpg` と `a.png` を `png` で書き出すなど）がある場合、v0.2.0 までは後の画像が先の結果を黙って上書きし（全件「成功」と数えられる）、v0.3.0 からは後の画像が「失敗」になって先の結果が残る。実行前の確認に、使用バージョンに合わせた警告が出る。

## レシピ
- 「**レシピ**」で `actions/*.json` の一覧・編集・新規作成・複製・削除ができる
- 編集中に検証する。JSON の誤りは保存できない。未知のコマンドや、書式にない params のキーは警告になる
  - PhotoCraft の CLI は params の誤りを黙って無視するため、警告は必ず確認する
- 右の「コマンドを探す」で、使用バージョンのコマンド一覧から ID・名前・メニューで探し、params の書式を見てレシピに追加できる
- 保存したファイルはアプリなしでも使える: `photocraft-cli batch --actions actions/<名前>.json --in <入力> --out <出力>`
- 書き方は配列の `{"command": …, "params": …}` が全版で読める。v0.3.0 からは `[ID, params]`・ID だけのステップや `{"steps": …}` も読めるが、v0.2.0 以前ではエラーになるので、アプリは警告を出す

## スモークテスト（ピン版と最新版の比較）
1. 「**スモークテスト**」を開く。ピン版（`.photocraft-version`）と最新版が未導入なら「未導入の版を導入」
2. 「**スモークテストを実行**」で、全レシピを `samples/smoke/in` に両方の版で適用する（出力は `out/smoke/<版>/<レシピ>`）
3. 判定（docs/upstream-tracking.md の判定ルールと同じ）

| ピン版 | 最新版 | 判定 |
|---|---|---|
| 成功 | 成功 | 互換（ピンを更新してよい） |
| 成功 | 失敗 | **破壊的変更**。レシピと docs/commands.md を直す |
| 失敗 | 成功 / 失敗 | 要確認（レシピか入力の問題） |

成功しても params が効いているとは限らない（CLI は params を検証しない）。params のキー名の変更は「本家の更新」のコマンド台帳の差分で確認する。

## 本家の更新
- アプリの起動時と 24 時間ごとに本家を確認し、確認待ちがあるとサイドバーに「本家の更新を確認（N 件）」が出る
- 「**本家の更新**」で見られるもの
  - **リリース**: ピンより新しいリリース、差分のコミット数、GitHub の差分ページへのリンク
  - **監視対象ファイル**（`.upstream/watched-paths.txt`）: 本家で最後に変わったコミットと、確認済みとして記録した SHA の比較。内容を確認したら「確認済みにする」で `.upstream/<key>.sha` に記録する（GitHub Actions の upstream-watch と同じファイル。コミットして共有する）
  - **コマンド台帳の差分**: ピン版と最新版の `commands --json` の比較。レシピで使っているコマンドが削除・書式変更されていれば赤で出す
- 本家の情報は GitHub API で取る。使えないときは、本家の履歴だけを持つ git の複製（ファイル本体は取らない）をアプリデータ領域に作って代用する（git が必要）

## ピン更新（手順をスキップできないウィザード）
本家に新しいリリースが出たときの、`docs/upstream-tracking.md` の「更新時の手順」を、飛ばせない形で進めます（「ピン更新」ページ）。4 つがすべて終わったときだけ、ピンを更新できます。

| 手順 | 終わりの条件（アプリが判定する） |
|---|---|
| ① 差分を確認する | 監視対象ファイルがすべて確認済みで、「差分・リリース・control-protocol などの変更を読んだ」にチェックした |
| ② スモークテスト | ピン版 → 更新先の版で実行した結果が「互換」で、**今のレシピ全体に対する結果**である（スモークのあとにレシピを直したら、やり直しが必要） |
| ③ レシピと台帳の見直し | レシピ・`docs/commands.md` を見直した（コマンド台帳の差分で、使用中のコマンドへの影響を確認できる）にチェックした |
| ④ 記録して更新 | 上の 3 つがそろっている。結果と修正内容を入れて実行する |

④ を実行すると、次の順に書き込みます（途中で失敗したらピンは変わりません）。
1. `docs/upstream-snapshot/<更新先>/` を作り直す（本家の資料・コマンド台帳・MCP ツール一覧。選択式）
2. 全レシピの `tested_with` を更新先の版にする（選択式）
3. `docs/upgrade-log.md` に 1 行追記する
4. `.photocraft-version` を更新先の版にする

変更したファイルは画面に出ます。コミットして共有してください。

## MCP 接続（Claude などから PhotoCraft を操作する）
「**MCP 接続**」で、MCP クライアントに貼る設定を作り、接続を確かめます。
- **ヘッドレス**（ウィンドウなし）: 読み取り・書き出しのルートフォルダを決めます（v0.2.0 以降は必須。ルートのフォルダは先に作っておく必要があり、無ければ画面から作れます）。
- **ブリッジ**（起動中の PhotoCraft アプリを操作）: 先にアプリを `photocraft --control <ポート> --control-token-file <ファイル>` で起動します。ルートはアプリの起動時に渡します（MCP 側では変えられません）。トークンの値は設定に書かず、ファイルで渡します。
- 設定は Claude Desktop / Claude Code の `mcpServers` 用 JSON と、`claude mcp add` のコマンドで出ます。
- 「**起動して確かめる**」は、同じ引数で `photocraft-cli mcp` を起動し、ハンドシェイクとツール一覧の取得をしてから止めます（MCP は標準入出力で話すので、サーバーはクライアントが起動します。アプリが常駐させることはしません）。
- ツール一覧は `mcp/tools-<版>.json` に保存でき、保存済みの別の版との違いも出ます。

## コマンド台帳
「**コマンド台帳**」で `docs/commands.md` の表（コマンド・params 例・用途・使用レシピ・検証日）を編集します。表の外の文章は変えません。
- 「レシピから収集」: レシピで使っているコマンドを足し、「使用レシピ」を最新にします（手で書いた用途や検証日は変えません）
- 「成功した実行から検証日を更新」: 実行履歴で成功した版と日付を反映します
- 使用中の版の `commands --json` にないコマンドは警告します

## GitHub Issue の起票（任意）
「本家の更新」ページの下で、更新を GitHub Issue にできます（`upstream` ラベル）。件名は GitHub Actions の upstream-watch・smoke と同じなので、どちらが先でも二重になりません。スモークテストで破壊的変更が出たときも、その画面から起票できます。
- 起票先（owner/repo）と GitHub トークン（Issues の書き込み権限）を設定します。起票先は、git の origin から決まります。
- トークンは **OS のキーチェーン**にだけ保存します（ファイル・履歴には書きません）。キーチェーンを使えない環境では、環境変数 `GITHUB_TOKEN` で渡します。
- 「本家の確認で見つけた更新を自動で起票する」は**既定でオフ**です。オンにすると、起動時と 24 時間ごとの確認のあとに起票します。初めてオンにすると、確認待ちの監視対象ごとに Issue ができます。

## 履歴
「**履歴**」に全実行が残る（使用版、レシピ内容の SHA256、入出力パス、実行コマンド全文、終了コード、ログ）。保存先は次のとおり。

| OS | 場所 |
|---|---|
| macOS | `~/Library/Application Support/craft-automation/runs.sqlite` |
| Windows | `%APPDATA%\craft-automation\runs.sqlite` |

同じ場所に、本家の確認に使う git の複製（`upstream.git`）も置く。消しても次の確認で作り直す。

## 外部との通信
- GitHub（本家のリリース一覧・CLI・資料の取得）だけ。画像やレシピは外に送らない
- Issue の起票を設定したときだけ、GitHub API にトークンを送って Issue を作る
- アプリは自分の PC（localhost）からだけ開ける。Streamlit の利用統計送信は切ってある（`.streamlit/config.toml`）
- リリース一覧は GitHub API（未認証で 1 時間 60 回まで）。使えないときは git のタグで代用する。環境変数 `GITHUB_TOKEN` があれば使う

## できないこと
- OS の通知: サイドバーの表示で代用しています（[ADR 0001](adr/0001-app-stack.md)）
- MCP サーバーの常駐: MCP は標準入出力で話すので、クライアントが起動します。アプリは設定の作成と接続の確認までです

## 困ったとき
| 症状 | 対処 |
|---|---|
| 「Python 3.10 以上が見つかりません」 | python.org から入れ直す。Windows は PATH のチェックを忘れずに |
| 導入で「HTTP 404」 | その版に、この OS 向けの asset がない。別の版を選ぶ |
| 導入で「SHA256 が一致しません」 | 通信の途中で壊れた可能性。もう一度導入する |
| リリース一覧が出ない | 社内ネットワークで GitHub が遮断されている可能性。タグを直接入力して導入する |
| 依存の導入に失敗する | `.venv` フォルダを削除してから起動し直す |
| MCP の接続テストが「cannot open automation write root」で失敗する | 読み取り・書き出しルートのフォルダを作る（画面の「ルートのフォルダを作る」） |
| ブリッジの接続テストが「No such file or directory」で失敗する | トークンファイルが無い。先に `photocraft --control …` でアプリを起動する |
| Issue を起票できない | 起票先とトークンを確認する。トークンには対象リポジトリの Issues の書き込み権限が必要 |
| 「ピンを更新」が押せない | ④ の見出しの下に、終わっていない手順が出ています。レシピを直したあとは②をやり直す |
